# 产品规格

M0-A v1.0 · 2026-09-27

## 1. 定位与目标

MonadBox 是面向个人、创作者、社区和小团队的稳定币支付工具集合站：通过一个链接，按事先明确的规则完成收款、退款和分账。品牌独立，不依附 NodeStake；借鉴 ArcBox 六工具思路，但不假设可以原样复制代码或跨赛事重复申报。

主参赛方向为 Consumer Products & Payments。官方重视初次使用体验、可编程支付和群体结算；这里是匹配判断，不是主办方对本项目的资格批准。[S01](../planning/SOURCES_AND_PROVENANCE.md)

产品完成目标是六个工具共用一套工作台。开发先完成 Group，再完成 Split 与组合场景，后续四工具依次交付。不能把未完成工具呈现为可用。

## 2. 用户与待验证需求

| 角色 | 任务 | 希望省去的工作 |
| --- | --- | --- |
| 小团队组织者 | 收齐费用、处理未成团退款 | 催款、转账截图、人工退款 |
| 合作伙伴 | 按约定获得分成 | 收款后再追问分钱 |
| 创作者/客户 | 交付成果并按约定付款 | 口头约定、一次性付款风险 |
| 活动组织者/参加者 | 报名与到场押金 | 手工核对与不透明扣款 |
| 社区奖励负责人/成员 | 向指定地址发奖、领取 | 批量转账和重复领取核对 |

以上均为产品假设，M2/M7 需要真实访谈与试用证据。首批用户优先已经持有稳定币的人；未接通法币渠道时不宣称银行卡支付或本地货币提现。

## 3. 首版边界

- 单链：Monad；开发默认测试网，主网另行放行。
- 单 Box 单 ERC-20 资产；优先验证 AUSD，不支持任意自填代币。
- 外部钱包先行。邮箱/Passkey 嵌入式钱包和 Gas 赞助是隔离适配项，未验收不展示成功能力。
- 一账户一主钱包；链上权益归钱包，不因修改账户邮箱或后台资料而迁移。
- 平台服务费暂为 0；网络费单独显示且不从应退本金中暗扣。
- 中文与英文文本结构同时设计，默认英文面向全球评审，可切中文；真实上线文案应完整校对。
- 平台提供规则执行工具，不承诺判断现实交付、提供保险、保证兑付或保证获奖。

不做：兑换、跨链桥、发币、收益理财、信用放贷、法币出入金、通用任意合约执行器、AI 资金裁决、完整商城/CRM、无限层工具嵌套。

## 4. 六工具规格

### 4.1 Group / 成团收款

场景：小组活动、联合采购准备金、社区共同预算。它保证的是已披露的成团与结算规则，不保证现实服务质量。

创建字段：标题、说明、公开规则摘要、代币、每份价格、最低参与数、容量、募集开始/截止、最早结算时间、固定收款地址或 Split 方案。每个钱包最多一份；地址数不是独立自然人数，不做防女巫承诺。

流程：草稿 → 发布上链 → 分享链接 → 参与者查看规则与付款 → 截止前可退出 → 截止后按人数确定成败 → 未成团领取退款 / 成团到结算时间后计入受益人可领取款。

关键约束：达到人数不提前关闭退出权；截止时才最终判断。组织者可以在结算前取消，使所有未结算款可退。截止后参与者不再拥有无条件退出权，付款前必须显著确认。组织者沉默不会无限锁款：满足时间与人数条件后任何人可触发确定性结算。

验收示例：最低 3 人，每人 30 个代币。2 人截止：每人 30 可退。3 人截止但尚未到结算时间：90 仍保留。到时结算 90；M2 使用 70/30 方案得到 63/27。以上不含网络费。

### 4.2 Split / 合伙分账

场景：联合创作、活动收入、团队服务费。只处理已无退款义务的最终支付；不是退款托管。

创建字段：标题、代币、2–20 个不重复非零收款地址、对应 basis points、付款说明；总比例必须为 10000。金额可由付款人输入，或创建者设为固定金额。方案发布后不可修改。

流程：创建固定方案 → 付款人确认受益人和不可强制追回提示 → 付款 → 合约按比例记录各方可领取款 → 各受益人领取。

尾差按固定最大余数法分配，见资金规则。单独 Split 不允许管理员事后退款；受益人自愿退回是独立交易。组合 Group 时复制并冻结同一分账方案，不能付款后替换受益人。

### 4.3 Deliver / 交付收款

场景：设计稿、短文稿、一次性代码交付；一位客户、一位服务者、一笔全额预付。

创建字段：双方钱包、价款、资金存入期限、工作时长、验收时长、争议处理时长、交付描述及私密附件约定。默认工作 7 天、验收 72 小时、争议 7 天；允许范围在合约版本中固定。

流程：客户存款 → 服务者期限内提交交付证据 → 客户主动接受或提出异议 → 接受或验收期届满未异议时可结算；未交付到期则退款。

异议期间暂停该订单结算。双方可签署一次性分配协议；到争议期限仍无协议则剩余托管款退给客户。这是明确偏向付款人的退出机制，不是平台判定服务者有错。服务者创建时也必须确认。

提交证据哈希只证明记录一致性，不证明质量或客户已成功下载。首版不保证数字文件绝对防复制。

### 4.4 Attend / 报名保证金

场景：免费或低门槛活动的到场押金；不是售票系统。

创建字段：固定押金、人数上限、报名截止、活动开始/结束、签到宽限期、申诉窗口、未到场扣款比例、固定罚款受益人、签到认证钱包。默认申诉 24 小时、争议 7 天；所有窗口发布后不可缩短。

流程：参与者存押金 → 报名截止前可退出 → 获组织者签到签名并提交 → 已签到押金可领取退款。活动取消后所有剩余押金可退。未签到者在申诉窗口内可提出异议；无异议且窗口结束后，按已披露比例分配。

签到依赖已披露的组织者证明，不声称链上知道实际出席。争议无法协商时到期退给参与者，主办方须接受该反滥扣款与反滥用之间的取舍。

### 4.5 Milestones / 分阶段付款

场景：小额固定阶段的创作与开发委托；一位客户、一位服务者，2–10 个阶段。

创建字段：双方地址、每阶段名称/金额/工作时长/验收时长、全额资金存入截止、争议时长。所有阶段价款一次预存，每阶段独立释放；下一阶段工作时钟从上一阶段确认结算起算，不能暗中缩短。

流程：全额存款 → 当前阶段交付 → 当前阶段验收/异议 → 接受后释放该阶段并启动下一阶段。未按时交付或订单取消时，未释放部分按规则退回；已经完成释放的阶段不可强制追回。

任何阶段的正式异议终止正常后续流程，双方就全部剩余托管款协商分配；超时则全部剩余款退客户。不实现跨阶段反复仲裁。

### 4.6 Rewards / 奖励领取

场景：社区贡献奖励、活动奖励、名单制补贴，不进行开放身份资格判断。

创建字段：批次名称、代币、最多 100 个不同地址及各自金额、领取开始与截止。合约逐项校验总额，一次全额入金后生效；上限须经 M0-C/M6 Gas 测试，必要时下调并版本化。

流程：导入并检查名单 → 显示总额和隐私提示 → 全额预存 → 指定地址领取 → 到期未领取部分由原创建者回收。

名单和金额公开上链，首版不宣传匿名或私密奖励。已生效名单不可编辑，创建者不得提前撤回；错名单需要另建批次，不得侵占已承诺款。

## 5. 共享账户与订单体验

工作台包含我创建的 Box、我参与的订单、待处理事项、可领取款、历史记录；状态按角色过滤。不要以网站数据库汇总数字假装可提余额。每笔金额同时注明网络、资产、权利状态及更新时间。

同一用户可以同时是创建者、参与者、受益人，但服务方与付款方必须分别签署其角色操作。公开链接仅授予查看，不授予提款或查看私密交付文件的权限。

## 6. 首条演示主线

两个合作方创建 Group，固定 70/30 分配、最低 3 人，每份 30。完成三个真实测试网付款，展示截止前退出、未成团退款另例，再展示成功组的时间锁、分配入账和双方提款。所有缩短演示窗口仅允许测试配置，并持续显示 Testnet。

M1 不需要先写 Split 合约；先支持单受益人结算。M2 用经测试的固定分账方案扩展，并保留旧版本可退出，不修改旧订单规则。

## 7. 质量与用户验证目标

内部目标而非既有成绩：找到 3–5 位真实潜在创建者；至少 5 位外部测试者独立完成流程。测量首次付款完成率、失败原因、退款可发现性、需要人工指导的次数、再次使用意愿。测试者的钱包数不等于真实用户数，不把自转账计为交易需求。

MVP 不承诺所有人五分钟内完成；先记录真实耗时。六工具最终均需具备创建、执行、失败恢复、资金退出和查询历史，不能只交付首页卡片。
