# 页面与交互规格

M0-A v1.0 · 本次仅交互/布局规格，无效果图、前端实现或实机视觉验收。

## 1. 设计方向

默认采用清晰、克制的模块化网页：浅色底、独立卡片、充足留白、轻量紫色品牌强调。不是交易终端，不使用价格行情墙、夸张收益数字、霓虹背景或难辨认的玻璃覆盖资金信息。若使用轻微透明层，仅用于导航，不影响对比度。

核心任务是“我需要收钱/付款/退款”，不是“学习链和合约”。但签名之前必须明确网络、代币、金额、受益人及退出规则，不能以简化为名隐藏风险。钱包连接不作为浏览公开内容的前置条件。

## 2. 信息架构与路由

| 路由 | 页面与访问 | 核心内容/主操作 |
| --- | --- | --- |
| `/` | 首页，公开 | 一句话定位、六工具卡片、三步说明、创建Box |
| `/tools/:tool` | 工具说明，公开 | 适用/不适用场景、退款摘要、创建入口 |
| `/create/:tool` | 创建向导 | 基础信息→资金规则→参与方→预览与签名 |
| `/b/:publicId` | 分享付款页 | 标题/创建者、状态、金额、期限、规则、当前可做动作 |
| `/b/:publicId/order/:orderId` | 订单详情 | 本人操作、资金流、链上确认、时间线；私密部分需授权 |
| `/app` | 工作台，登录 | 待处理、可领取、我创建/参与的Box、最新状态 |
| `/app/boxes/:id` | 创建者管理 | 规则只读、参与列表、取消/结算等合法动作、分享 |
| `/app/activity` | 记录，登录 | 按工具/身份/资金状态筛选，导出本人记录 |
| `/app/settings` | 设置，登录 | 语言、时区、通知、钱包只读及风险说明 |
| `/help/refunds` | 帮助，公开 | 六种退款机制、如何链上退出、Gas说明 |
| `/status` | 状态，公开 | 当前环境、网络、构建、索引延迟、已知故障，不泄露内部凭据 |
| `*` | 404 | 无效链接/已隐藏页面的区别与返回入口 |

公开Id不是授权凭据。账号间不可通过更换路由查看交付附件。六工具尚未全部上线时，未完成工具保留说明卡及“尚未开放”，不得跳进假交易页面。

## 3. 布局与视觉令牌

下列为待实现基线，不是已有样式代码。

| 项目 | 规格 |
| --- | --- |
| 视口验收 | 360、390、768、1280、1440px；200%文字缩放 |
| 容器 | 营销/工作台最大1200px；付款正文最大640px；创建向导最大1040px |
| 外边距 | 小屏16px，中屏24px，大屏32px |
| 间距尺度 | 4/8/12/16/24/32/48/64px |

| 圆角 | 输入/按钮10px；卡片16px；不把所有元素做成胶囊 |
| 基础颜色 | 背景#F7F8FC、卡片#FFFFFF、正文#171923、次要#596174、边框#DDE1EB；强调#5B3FD6 |
| 行为反馈 | 成功/警告/失败同时使用图标与文字，不仅靠颜色 |
| 控件 | 点击区域至少44×44px；清晰focus ring；按钮主次明确 |
| 动画 | 常规120–200ms；尊重prefers-reduced-motion；无连续炫光 |
| 可访问性目标 | 常规文字对比度至少4.5:1；键盘完整操作；上线前实测 |

默认先交付完整浅色主题，不把暗色主题作为M1阻塞。开发后必须实际截图检查，不能以规格或生成图片替代验证。

## 4. 首页

顶部：MonadBox标识、工具、我的Box、语言、连接钱包。Hero只放一句定位与“创建Box/查看工具”。下方桌面3×2、平板2列、手机1列工具卡，卡片显示一个场景句与明确动作，不堆积协议名。

用真实流程示例解释“创建规则→分享链接→收款与结算”。没有验证前不显示用户数、交易额、节省成本百分比或安全认证。页脚保留环境、条款、隐私和帮助。

## 5. 创建向导

Step 1 选择工具/基础信息；Step 2 金额、时间与退出规则；Step 3 参与方/名单/分账；Step 4 完整预览、最坏资金情形、签名发布。自动保存仅是草稿，不自动上链。

桌面左侧表单、右侧持续更新的规则摘要；手机把摘要放在发布确认前，不在每个字段后重复。后台保存失败时保留本地未发布表单并提示，不能显示“已保存”。切换钱包后提示草稿所属身份并要求重新核对。

| 工具 | 必须强调的表单内容 |
| --- | --- |
| Group | 截止前可退出、截止后不再任意退出；成团≠交付验收；取消与结算条件；地址数≠自然人数 |
| Split | 受益人和比例合计100%；精确地址确认；最终付款无法强制撤回；尾差预览 |
| Deliver | 未按时交付退款；验收期不异议可结算；争议超时偏向客户退款 |
| Attend | 扣款最坏金额、签到方信任、申诉截止、组织者不响应的退出规则 |
| Milestones | 全额预存但按阶段释放；未释放才可退；每阶段时钟起点 |
| Rewards | 名单和金额公开、总额入金、过期仅收回未领取资格部分；发布后不能改名单 |

验证必须字段就地呈现。日期控件显示用户当地时间和时区，最终确认再显示UTC绝对时间。价格不接受科学记数法、负数、超精度或含糊千位分隔。中文和英文都不用无资产标识的 `$30` 代替 `30 AUSD`。

## 6. 付款页：前五分钟

阅读无需登录。首屏依次显示：创建者/标题→当前状态→本次金额/资产/网络→截止与资金规则摘要→主按钮。收款人完整地址可展开，付款摘要必能核对。

用户点击后：连接钱包→确认网络→余额/授权预检→精确额度approve（需要时）→业务付款签名→发送中→链上已收录→完成确认。可合并的步骤必须以钱包与token实测支持为前提；不能承诺所有钱包一次签名。

固定底部CTA只用于手机，不遮住条款或系统safe-area。可见提示“你正在测试网操作，代币没有真实价值”。Production仍跑测试网时照样显示，不能因域名正式就移除。

### 交易状态与文案

| 状态 | 文案/动作 |
| --- | --- |
| 未连接 | 连接钱包继续；不清空表单 |
| 错网络 | 切换到Monad Testnet；未切换不发送 |
| 代币不足/MON不足 | 分别显示所缺资产；不把代币足额当Gas足额 |
| 待授权 | 授权本次额度；明确这还不是付款 |
| 钱包拒签 | 已取消签名，尚未付款；可重试 |
| 已授权但付款失败 | 授权已完成，付款未完成；显示现有授权与可重试条件 |
| 广播/确认中 | 显示可复制hash与查询入口；禁用重复付款，不锁定整个网站 |
| 确认超时 | 尚无法确认结果；先查询原交易，不提示直接再付一遍 |
| 已收录未最终确认 | 已收录，仍在确认；不显示可退款已到账 |
| 已确认/索引落后 | 链上确认、记录同步中；以直接验证回执为依据 |
| 失败/reverted | 原因＋恢复动作；不泄露服务器堆栈 |
| 替换/取消交易 | 跟踪原nonce的替代结果；不可把两个hash计成两次付款 |

## 7. 各工具详情主动作

| 工具/角色 | 常见主动作 | 不可操作时 |
| --- | --- | --- |
| Group/参与者 | 付款、截止前退出、领取退款 | 显示为什么已过退出期或尚未达到退款条件 |
| Group/组织者 | 分享、取消、到期结算 | 已结算不能取消；临近竞态提示链上顺序 |
| Split/受益人 | 查看份额、领取 | 区分待入金与credit=0，不虚构余额 |
| Deliver/客户 | 查看交付、接受、提出异议 | 显示绝对reviewDue及后果 |
| Deliver/服务者 | 提交、主动退款、到期结算 | 争议中只显示协议/超时机制 |
| Attend/参与者 | 报名、签到、申诉、领回押金 | 签到和申诉各自倒计时，清晰标记不同截止 |
| Milestones/双方 | 当前阶段动作 | 未来阶段只读、已释放不可撤回 |
| Rewards/获奖者 | 查看资格、领取 | 未在名单/未开始/已领取/已过期分别提示 |
| Rewards/创建者 | 分享、到期回收 | 已成为他人credit的款永不显示可回收 |

拒绝/取消/放弃权益前使用二次确认，显示具体资产金额和地址；普通浏览或复制链接不弹窗。部分功能停用不隐藏既有款项退出入口。

## 8. 工作台与统一金额卡

优先排列“需要我处理”→“可领取”→“进行中”→历史。卡片分别显示 locked、credit、已转出，不简单相加为可用余额。跨token不合成一个假美元数字；不跨测试网/主网累计。

活动时间线包含操作人、动作、金额、链上/链下类型、确认状态和时间。下载附件行为不是链上交付完成证明。本人记录CSV对以=、+、-、@开头的用户文本做公式注入处理。

## 9. 必须覆盖的页面状态

每条核心路由具备 loading、empty、error、offline/reconnecting、permission denied、not found；写入页面还具备 pending signature、pending transaction、stale data、intake paused、readonly old contract。骨架屏不能先显示一个假的余额。

错误回退保留表单和原交易hash；刷新页面后通过订单/nonce恢复待确认操作。收到多个通知只产生一次动作入口，不弹多个要求签名的窗口。

## 10. 体验验收

在手机和桌面验证创建→分享→付款→退款/结算→领取全流程；另一人不经口头指导能辨认当前钱的位置及下一步。测试键盘焦点、屏幕阅读器label、长中文/英文、长地址、200%缩放、慢网、钱包拒签和页面刷新。

内部预算：公开页初始首方JS压缩后<=250KiB，钱包SDK按需加载；移动端关键首屏可见目标LCP<=2.5s、CLS<=0.1，均需记录测试设备/网络/工具，不作为已实现宣传。
