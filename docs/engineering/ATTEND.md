# Attend 报名、签到与退出

入口 `/create/attend`：固定每人押金、最多200个名额、报名/退出截止、活动起止、签到窗口、申诉截止、1–30天争议期、0–100%缺席扣款、签到方和罚款受益人。发布钱包是组织者。规则预览显示最坏扣款和签到信任边界；实际报名先单独授权准确押金，再明确支付。

合约 `AttendanceBondV1` 版本1，固定资产与管理员；管理员仅可暂停新增活动和报名，不能更改已发布规则、受益人或阻止退款提款。没有全员结算循环；每位参加者独立状态和款项。

## 操作

1. 报名截止前可退出，押金记入本人 credit；同一地址不能重新报名，退出释放名额。
2. 签到方打开原公开链接，在“要查询的参加者钱包”填写该参加者，核对后签署到场证明。双方直接交换证明 JSON 和临时签名。
3. 参加者或代提交者核验证明，明确提交签到交易。只有在签到窗口及证明期限内成功上链才完成签到，押金全额归属参加者 credit。
4. 未签到者在签到截止至申诉截止间提交证据摘要，个人押金进入争议；其他人的退款和缺席结算照常进行。
5. 未签到也未申诉者在申诉截止后可结算：`floor(deposit × bps / 10000)`归固定罚款受益人，余款归参加者。
6. 争议中组织者可全退；参加者与组织者也可签署精确分配协议，款项只归参加者与固定罚款受益人。组织者可以与罚款受益人是不同地址。争议到期全退参加者。
7. 组织者可在申诉截止前取消活动，尚未处理的个人押金可逐人全退。已签到、已退出或已结算款不能再次退款。
8. credit 单独提款后才进入钱包。查看他人参加状态时，“可领取余额”和“已转入钱包”仍属于当前连接的钱包。

## 证明与恢复

签到 EIP-712 域为 `AttendanceBondV1`、版本1、chainId10143、原合约地址。消息绑定 schemaVersion、boxId、termsHash、attendee、signer、issuedAt、deadline、个人 nonce；过期、活动/人/签到方错误和重放均拒绝。申诉协议使用共用完整域与资金字段，`orderId=keccak256(abi.encode(boxId, participant))`，只处理该人的押金。

证明是固定签到方的声明，不证明客观物理位置。签发签名与交易上链是两步；应留出提交时间，未及时提交且未申诉可能按规则扣款。签名前核对原收款人、金额、期限和域；持有有效签名的人可代提交。

原始签到或协议签名只留页面内存，不进入云端 API、D1、localStorage 或日志。显式提交后签名作为交易参数在链上公开。恢复记录保存公开证明与 calldataHash；回执核验从原链交易读取签名，重建完整参数，检查账户 nonce、固定调用、事件、canonical/finalized 和读回。未知结果先恢复，不能重复报名或重复提交。

已有模块草稿、云端发布、工作台、公开链接及旧版本核验均复用，M4无需新增D1迁移。实际公开部署与活动、签到方操作、真实手机钱包仍待外部验收；公众资金开关维持关闭。
