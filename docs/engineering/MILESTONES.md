# Milestones 分阶段托管

入口 `/create/milestones`。固定客户、服务者、付款截止、争议期限及2–10个阶段。每阶段包含公开名称、验收标准、正金额、1–720小时工作期和1–168小时验收期；争议期1–30天。总额用整数相加，所有阶段、文本、金额与时长均纳入规则哈希，发布后不可改。

## 付款与阶段推进

- 客户一次全额预存原生 MON，无代币授权步骤。首阶段时钟从链上实际付款开始。
- 只有当前阶段可交付。服务者提交证据摘要后启动该阶段验收期，重复提交不能重置时钟。
- 客户接受，或验收截止仍未提出正式异议，才将当前阶段金额归入原服务者 credit。
- 下一阶段工作期从上一阶段实际结算时开始；不会因上阶段延后结算而提前消耗下一阶段期限。
- 每个阶段操作参数和事件都绑定阶段序号。前端准备时再次核对所见阶段，旧页面或旧交易无法接受、退款或提交到下一阶段。
- 已释放阶段总额、全部剩余托管款、阶段进度、截止时间、个人 credit 与提款分别显示。服务者可分次提款。

## 终止与争议

未交付到期、服务者主动退款或争议到期，会终止整个剩余计划，把全部未释放款归还客户。已经释放或已提款的阶段款不可强制追回，客户也不能无条件提前取消已付款订单。

任一阶段正式争议停止全部后续阶段。双方只能就**全部剩余款**签署一次协议，或者等待争议到期全退客户。协议结算后计划结束，不恢复下一阶段。

双签与临时签名交换复用[Deliver](DELIVER.md)，域名称为 `MilestoneEscrowV1`，`orderId=boxId`，消息额外核对当前 `stageIndex`。remaining 是整个剩余计划款，不是当前阶段金额。原始签名只保留页面内存，显式提交后进入公开链交易；恢复记录只保存公开协议及调用哈希。

## 分阶段私密文件

选择文件所属阶段，每阶段最多5件、每件10 MiB，原有类型、SHA-256、双方权限和存储环境检查不变。预留与上传时都要核对当前阶段；阶段已推进后旧预留不能上传。先前ready文件仍可由固定双方读取，终结后的90天访问窗口适用于整个订单。

沿用`0004_delivery_files.sql`，无需新迁移；不建立公开文件地址，不改变链上计时。实际R2资源与物理保留政策仍在外部验收中。网站或存储不可用时，双方仍可按原合约进行结算和退出。

合约版本1，与先前Deliver及Attend部署、ABI、规则完全独立。暂停只限制新建与入金；现有阶段交付、退款、协商、到期退出及提款仍有效。
