# Rewards 固定名单奖励

入口 `/create/rewards`。1–100个不同地址，每笔金额为正数，MON最多18位小数；按地址数值排序，金额始终跟随原地址。CSV/TXT只在浏览器内读取，支持`address,amount`表头、逗号或制表符。不能夹带姓名或私密联系方式，名单与金额会公开。

## 原生 MON 单笔发布

1. 预览排序名单、总额、领取起止时间，保存本地草稿；登录后显式复制到云端，冻结规则、salt和部署身份。
2. 准备发布时核对当前账户、nonce、本金和网络费。用户确认后，`createAndFundBatch` 在同一笔交易中建立名单并收足全部 MON，value 必须等于名单总额，失败全部回滚。
3. 核对原调用、BoxCreated、最终性和链上规则后才发布公开链接。

没有 ERC20 授权步骤。发布中断先用原哈希或本地交易历史恢复；无哈希时按原账户和 nonce 找回。unknown 不自动解冻或重发。原始签名不保存。

## 领取与到期

- `claimStart <= block.timestamp < claimDeadline`，每个地址只领取一次。链上任何人可以代触发，资金始终归原名单地址；页面提供当前钱包领取。
- claim先记入受益人credit，提款另需一笔明确交易。credit尚未提款不代表未领取。
- 截止后仅原创建者可回收尚未claim的locked金额，再单独提款。所有已有credit仍保留给原受益人。
- 不修改名单、不提前取消、不提前回收；暂停新增业务不影响已有领取、到期回收和提款。
- 链上名单、金额合计与交易 value 与原生款项核算一致。管理员不能改变收款人或提走奖励。

## 上限与测试

本地100地址实际创建、领取、回收均有Gas测量；自动化预算分别1000万、25万、20万。精确数值和调用名由浏览器测试写入`artifacts/rewards-gas-*.json`并作为CI证据保留。样本、编译参数和 Anvil 均是本地环境，不能用来承诺真实Monad费用。

真实网络上线前，必须复测原生 MON 的最大名单、领取和回收费用及实际交易/区块限制。若不满足预算，先下调并版本化新部署上限；不能改变已发布名单。

RewardsDistributorV1是独立版本1合约；没有新数据库迁移。公开业务开关继续默认关闭，真实登记与资金操作遵循外部验收。
