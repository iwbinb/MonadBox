# Rewards 固定名单奖励

入口 `/create/rewards`。1–100个不同地址，每笔金额为正数，AUSD最多6位小数；按地址数值排序，金额始终跟随原地址。CSV/TXT只在浏览器内读取，支持`address,amount`表头、逗号或制表符。不能夹带姓名或私密联系方式，名单与金额会公开。

## 发布必须完成两步

1. 预览排序名单、总额、领取起止时间，保存本地草稿。登录后显式复制到云端，冻结原规则、salt和部署身份。
2. 明确签署总额的准确授权。授权确认后仍为prepared，公开链接不能访问，资金尚未入金。
3. 点击“准备全额入金发布”。服务端重新验证原授权，读取当前实际nonce；即使中间另发交易也不能假设nonce仅加1。再次明确签名后，`createAndFundBatch`在同一笔交易中建立名单并收足全部金额，失败全部回滚。
4. 严格核对原调用、BoxCreated、最终性和链上规则后才发布公开链接。

两次签名各有独立意图。第二步意图内保留第一笔完整公开证据：id、nonce、准备块、到期时间、hash、确认块和块哈希。并发准备只保留一个后续意图；unknown不会自动跳步、解冻或重发。原始签名不保存。

发布中断时先用原哈希或本地交易历史恢复。若准确授权已经成功但最终放弃发布，授权仍可能存在；用户可用钱包核查并撤销剩余额度。撤销和重建都不能把未知旧交易当成未发送。

## 领取与到期

- `claimStart <= block.timestamp < claimDeadline`，每个地址只领取一次。链上任何人可以代触发，资金始终归原名单地址；页面提供当前钱包领取。
- claim先记入受益人credit，提款另需一笔明确交易。credit尚未提款不代表未领取。
- 截止后仅原创建者可回收尚未claim的locked金额，再单独提款。所有已有credit仍保留给原受益人。
- 不修改名单、不提前取消、不提前回收；暂停新增业务不影响已有领取、到期回收和提款。
- 链上名单、金额合计与实际代币增量一致。管理员不能改变收款人或提走奖励。

## 上限与测试

本地100地址实际创建约675.7万Gas，领取约21.7万、回收约12.9万；自动化预算分别1000万、25万、20万。精确数值和调用名由浏览器测试写入`artifacts/rewards-gas-*.json`并作为CI证据保留。样本、编译参数和MockToken均是本地环境，不能用来承诺真实Monad费用。

真实网络上线前，必须复测官方资产的最大名单、领取和回收费用及实际交易/区块限制。若不满足预算，先下调并版本化新部署上限；不能改变已发布名单。

RewardsDistributorV1是独立版本1合约；没有新数据库迁移。公开业务开关继续默认关闭，真实登记与资金操作遵循外部验收。
