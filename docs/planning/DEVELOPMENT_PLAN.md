# 分阶段开发与验收计划

M0-B更新 · 2026-09-27。旧两Worker方案已由用户最新决定替换为一个monadbox Worker+dev Preview。工程基础与远端部署分别报告；本地测试不替代远端资源/触发器验收。

## 1. 执行规则

读取远端 → 长期dev开发 → 本阶段测试 → dev→main PR → 报告并停止。Bill决定合并与下一阶段。不强推、不删除dev、不自动连续开发后续模块。

终态保留六工具，先Group，再Split组合，后续四工具逐个交付。未完成工具明确未开放，不把卡片或路线图当完成产品。“开发完成”“本地测试”“远端部署”“真实链上验证”“用户验收”分别记录。

## 3. M0-A：已交付的规格

README、AGENTS、文档索引、产品、资金状态、UI、架构、数据/API、合约、安全、部署、计划、门禁、来源与验收。六工具均有角色/字段/正常异常流程；Group→Split不绕过退款义务。历史M0-A记录保留，不将之后工程结果倒写为当时已实现。

## 4. M0-B：工程基础与远端验收分开

B-01 建立React/TS/Vite、Hono、shared schema、精确依赖及lockfile、环境示例和脚本；Foundry预留目录/候选配置，实际版本与编译器验证留M0-C。

B-02 首页、六工具说明、工作台空态、帮助/状态/404、中英文、移动布局、SPA深链接/API404；不显示假余额、不开放资金动作。

B-03 配置/chainId/namespace/allowlist校验，缺配置、主网或跨环境一律禁写。初始远端只读，不需要真实资源或secret。

B-04 D1基础迁移、原子nonce/唯一键/事务回滚、私密R2授权、Queue幂等/重试/死信最小验证；只在内部测试入口，不对公网开放未鉴权诊断。

B-05 格式、lint、typecheck、unit/runtime、build、E2E及只读CI；无资金私钥、无部署权限、无自动合并。

B-06 用户在控制台连接一个monadbox Worker，main生产、dev Preview。生产和预览资源后续隔离绑定。Preview不消费队列/运行Cron，远端后台需另行批准测试方案。

## 5. M0-C：Monad最小真实验证

C-01 官方资料和实际RPC双重核对chainId、区块、Gas、回执、日志、explorer和限流；记录时间/端点不记录私钥。

C-02 验证AUSD代码、精度、approve/transfer及测试资产来源，不凭symbol认币。

C-03 独立测试探针合约完成整数入金和退款；不将探针当业务模块完成。C-04 钱包连接、切链、拒签、精确授权、付款、确认、刷新、退款和重复请求；EOA/EIP-1271分别记录。C-05 锁定Foundry、编译器、EVM target与最终确认策略，保存部署/交易/ABI/构建证据。

C-T01 识别10143并拒错链；C-T02 官方资产实际调用；C-T03 钱包→合约→原地址真实测试网路径；C-T04 Approve不是Funded；C-T05 拒签/revert/未知回执不假成功；C-T06 重复退款失败且本金守恒；C-T07 日志重复/乱序/回滚fixture投影一致。

缺安全签名授权时只做只读/本地测试，真实交易项保持未通过。Mock不替代官方资产验证，不广播主网。

## 6. M1：Group

GroupEscrowV1、单受益人、创建/分享付款、参与退出、截止成败、取消退款credit及提款、工作台/事件同步；只开放Group。

| ID | 测试要求 |
| --- | --- |
| GR-01 | 未达最低人数截止后各份可退、组织者不能提 |
| GR-02 | 达标但未截止仍可退，人数/locked同步减少 |
| GR-03 | deadline前1秒/等于/后1秒唯一合法动作，不依赖抢先finalize |
| GR-04 | 满额/重复参加/退出重进/重复退款拒绝 |
| GR-05 | READY未到settleNotBefore不能结算，到期任何人可触发 |
| GR-06 | 取消结算竞态只成功一条，已退出不重复分配，已结算不再退 |
| GR-07 | 暂停入金不妨碍既有退款/到期/领取 |
| GR-08 | 360/390px、拒签、刷新、RPC异常、索引迟到均可解释 |

## 7. M2-A：Split与组合

不可变Split、2–20收款人、整数尾差、独立最终付款与credit；GroupV2发布时冻结方案、同交易分配；旧GroupV1退出保留。

SP-01 权重/零地址/重复/长度拒绝；SP-02 分配和恰等于入金、每方误差小于1最小单位；SP-03 nonce不重复；SP-04 某方提款失败不抹权益或阻他人；SP-05 Group失败只退款不分账；SP-06 成功只分一次、不可换方案；SP-07 旧版可退出。

演示未成团退款与达标结算，区分credit与到账。到PR停止，不顺便加入后四工具。

## 8. M2-B：体验与外部验证

根据实测优化首次付款、失败提示、刷新恢复、手机布局与退款入口。至少一种桌面外部钱包和一种手机钱包实测，不笼统宣称全部支持。

嵌入式/代付先核对Monad、签名恢复、费用配额、资源隔离与条款，最多选择一种供应商，不能为凑奖叠加。未通过保留正常外部钱包。

目标而非既有成绩：3–5位潜在创建者访谈、至少5位外部试用者；记录任务耗时、成功/失败、求助与复用意愿。拒绝/无需求也记录，不把同人多地址当多用户。

## 9. M3：Deliver

交付单次委托、私密文件、验收、异议、双签分配和超时退出。

DL-01 未交付到期退；DL-02 接受仅给原服务者；DL-03 无异议过review可结算、有异议禁止；DL-04 重复提交不重置期限；DL-05 双签篡改/重放/错链/过期拒绝；DL-06 争议超时退剩余；DL-07 非双方不能下载；DL-08 明示沉默结算和争议默认退款的双方风险。

## 10. M4：Attend

报名押金、固定签到证明、申诉/未到场分配、取消与领取；不是票务市场。

AT-01 截止前退出；AT-02 错签到方/活动/地址/重放拒绝；AT-03 签到全退不再罚；AT-04 申诉窗口内不结算未到场；AT-05 单人争议不阻他人；AT-06 取消只退未处理；AT-07 争议超时/无异议罚款符合本金守恒；AT-08 最后申诉时间与信任假设可发现。

## 11. M5：Milestones

2–10阶段、全额预存、逐阶段提交验收、剩余款和终止。

MS-01 未来阶段不提前领；MS-02 下一阶段时钟从上一阶段实际credit起算；MS-03 已释放不回滚、未释放到期可退；MS-04 争议停后续且仅处理全部剩余；MS-05 重复接受/协议不二次分配；MS-06 总额与阶段金额守恒。

## 12. M6：Rewards

显式名单、1–100地址实际Gas评估、全额预存、固定地址领取、过期回收。

RW-01 地址唯一/金额正；RW-02 链上合计等于实际入金；RW-03 非名单或重复领取失败；RW-04 起止时间边界；RW-05 已claim为credit但未withdraw不被回收；RW-06 不改名单/提前撤回；RW-07 最长列表Gas可行，否则发布前下调并版本化。

## 13. M7：发布与参赛

完整资金正常/异常/超时/重复回归；钱包兼容、实际手机截图、可访问性、性能；依赖/权限/独立安全复核、条款、事故退出。未通过G-07则保持测试网。

材料包括真实支持工具、需求与反馈、架构、真实演示录像、代码基线、地址与交易、限制、ArcBox来源与新增、赞助集成证据。未完成工具不伪装可用。G-08核实完整规则和截止时区，未取得证据不宣称已提交或满足全部奖项条件。

## 14. 阶段报告格式

范围/未完成项；dev提交和PR、main变化；实际命令与退出码/环境/证据；开发和生产实际URL/构建ID（没有就明确没有）；阻塞和资金权限变化；下一阶段。报告后停止。
