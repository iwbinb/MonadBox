# 分阶段开发与验收计划

M0-A v1.0 · 2026-09-27 · 本文是执行计划，不是已完成清单。

## 1. 执行规则

一个阶段一个可审阅结果：读取远端 → 在长期 `dev` 开发 → 执行该阶段测试 → `dev → main` PR → 报告 → 停止，由 Bill 决定合并和下一阶段。不会在本次 M0-A 自动展开 M0-B。阶段可因真实外部权限而部分完成，但必须明确未验收项，不能用模拟结果补勾。

产品终态仍是六工具。先跑通 Group，再做 Split 组合，后续四工具逐个交付。进度不足时可以展示已完成主线并标明未开放工具，但不能把六工具路线图改写成已经完成六个工具。

“完成开发”“本地测试通过”“远端部署成功”“真实链上验证通过”“用户验收”是五种不同状态。每次报告应分开列明。

## 3. M0-A：规格交付

产物：根README、AGENTS、文档导航；产品、资金状态、UI、架构、API/数据、合约、安全、部署；本计划、决策/门禁、来源/复用、验收记录。

验收：六工具均有目标用户、字段、正常流程、退出/异常、实施阶段；Group与Split组合不绕过退款义务；权限和时间规则可对应到测试；所有相对文档链接可解析；没有业务代码或部署宣称。Git写入dev并建立PR，main仍由用户合并。

## 4. M0-B：工程与部署基础

### 工作内容

B-01 锁定工具版本，建立React/TS/Vite、Hono Worker、shared schema及Foundry工程目录；提交lockfile、环境示例、可用脚本。

B-02 建立首页/工具说明/工作台空态和共享组件骨架，不用假资金填充；配置SPA深链接和API404。

B-03 建立配置schema、环境/chainId/资产allowlist校验，缺配置或跨环境时禁止写操作。

B-04 建立D1基础migration和事务/唯一键测试、私有R2受限读写、Queues幂等与死信处理的最小验证端点或测试入口；任何验证端点不能无鉴权进入正式站。

B-05 建立lint、typecheck、unit/runtime tests、build、基础E2E及GitHub CI；仅最小权限，不放链上私钥。

B-06 用户授权连接Cloudflare后建立dev/prod两个独立Worker，分别监听dev/main，隔离D1/R2/Queues和配置。

### 验收

| ID | 必须的证据 |
| --- | --- |
| B-T01 | 从干净检出安装、lint/typecheck/test/build命令退出码均为0；记录准确工具版本 |
| B-T02 | 首页与深链接可加载；未知API返回JSON404而非HTML |
| B-T03 | dev写入不可在prod读取；私有R2未授权不可下载 |
| B-T04 | 重复消息不会重复产生业务记录；失败消息能重试并进入死信 |
| B-T05 | 缺失secret、错chainId、错Worker目标时fail closed |
| B-T06 | dev新提交自动部署，prod保持原构建；记录实际构建ID和URL |
| B-T07 | 用户合并本阶段PR后，main自动部署成功；之后补录结果，不在合并前宣称已通过 |

停止点：PR提交时可为“开发/预览已验收，正式部署待用户合并后验证”。若Cloudflare权限未就绪，交付可运行工程及具体阻塞清单，不能标整个M0-B完成。

## 5. M0-C：Monad最小真实兼容验证

### 工作内容

C-01 从官方资料和实际RPC双重核对chainId、区块、Gas资产、回执、日志、explorer与可用性；记录测试时间/端点而不记录私钥。

C-02 验证AUSD候选地址代码、metadata精度、approve/transfer行为和测试资产获取；禁止仅凭symbol接受任意token。

C-03 用独立测试用最小托管/退款合约验证整数金额、实际入金和退款。该探针合约不是生产业务模块，不把它列成六工具完成。

C-04 测试钱包连接、网络切换、拒签、精确额度授权、付款、等待确认、刷新恢复、退款、重复请求；智能钱包签名与EIP-1271另列支持矩阵。

C-05 确定Solidity/EVM target、实际可用最终确认策略和索引回退；在文档保存合约、交易、区块、ABI及构建证据。

### 验收

C-T01 正确识别10143并拒绝错误链；C-T02 官方测试资产实际调用而非只读网页；C-T03 钱包→合约→原付款地址的完整真实测试网资金路径；C-T04 Approve不误认为Funded；C-T05 拒签/revert/未知回执不写假成功；C-T06 重复退款失败且本金守恒；C-T07 原始日志重复/乱序/回滚fixture投影一致。

真实链上验证需安全签名条件和用户明确授权。没有时可完成只读/本地测试，但C-T03等保持未通过。Mock token只用于隔离测试，不能替代AUSD兼容验收。M0-C不广播主网。

## 6. M1：Group

交付：GroupEscrowV1、固定单受益人、创建向导、分享付款页、参与与退出、截止成败、取消、退款归属及提款、工作台和事件同步。能力开关只开放Group。

| ID | 测试要求 |
| --- | --- |
| GR-01 | 未达最低人数截止后，各份本金可退，无组织者提款 |
| GR-02 | 已达标但未截止仍可退出，人数和locked同步减少 |
| GR-03 | deadline前1秒/等于deadline/后1秒对应唯一合法动作；不依赖先手finalize |
| GR-04 | 满额、重复加入、退出后重进、重复退款均被正确拒绝 |
| GR-05 | READY但未到settleNotBefore不得结算；到期可由任何人触发 |
| GR-06 | 取消/结算竞态只成功一条；已结算不能退款；已退出份额不重复处理 |
| GR-07 | 入金暂停不阻断既有退款、到期处理或领取 |
| GR-08 | 360/390px实际操作、刷新恢复、拒签、RPC异常、索引延迟可解释 |

资金不变量使用Foundry随机序列测试；记录执行种子/次数/结果。E2E正常和退款各完成一条真实测试网路径。没有这些证据不以页面可点击替代完成。

## 7. M2-A：Split与组合

交付：不可变Split方案、2–20收款人、整数尾差算法、独立最终付款和credit提款；GroupEscrowV2发布时冻结分账；统一记录展示，多方互不代管私钥。

SP-01 权重/零地址/重复地址/超长列表拒绝；SP-02 任意总额与比例分配总和精确等于入金，每方误差小于1最小单位；SP-03 付款nonce不重复记账；SP-04 某方提款失败不抹掉其权益或阻止他人提款；SP-05 Group失败只退款、不分账；SP-06 Group成功只分配一次，计划发布后不可改；SP-07 旧GroupV1退出仍可用。

演示包含未成团退款样例与达标结算样例，清楚展示credit和实际到账差别。停止于PR，不顺便加入四个后续工具。

## 8. M2-B：使用体验和用户验证

优先改善实测摩擦：首次付款步骤、错误提示、交易恢复、手机布局、退款入口。选择至少一种桌面外部钱包和一种手机钱包测试，不假设所有钱包都兼容。

可选嵌入式钱包/Gas赞助：先核对支持的Monad网络、签名能力、密钥控制/恢复、费用/配额、跨环境隔离及供应商条款，再决定接入一种。不能同时堆叠两个钱包供应商以凑专项奖。失败时保留已正确工作的外部钱包路径，功能明确不开放。

用户验证目标：3–5位潜在创建者访谈，至少5位外部测试者尝试完整流程；记录任务、完成/失败、真实耗时、求助点及反馈，不收私钥，不把同一人的多个地址当多位用户。用户拒绝/没有需求也应记录。

## 9. M3：Deliver

交付完整单次交付、私密文件、验收、异议、双签分配、超时退出与双方工作台。

DL-01 未交付到期全退；DL-02 主动接受只向原服务者归属；DL-03 review窗口边界无异议可结算，有异议禁止正常结算；DL-04 重复提交不重置时钟；DL-05 双签篡改/重放/错链/过期拒绝；DL-06 争议超时退剩余本金；DL-07 非双方无法下载私密文件；DL-08 页面显著解释沉默后结算和争议超时退款的双方风险。

## 10. M4：Attend

交付报名押金、固定签到方证明、申诉与未到场处理、活动取消、退款/罚款记录；不是票务市场。

AT-01 报名截止前退出；AT-02 错签到方/错活动/错地址/重放证明拒绝；AT-03 已签到全退不再罚没；AT-04 申诉窗内不能执行未到场结算；AT-05 一人争议不阻塞其他人；AT-06 取消只退未处理款；AT-07 超时争议退款/无异议按比例分配，整数本金守恒；AT-08 假设和最后申诉时间在手机首屏可发现。

## 11. M5：Milestones

交付2–10阶段全额预存、逐阶段提交与验收、当前阶段时间、已释放/未释放余额、订单终止。

MS-01 未来阶段不能提前领取；MS-02 下一阶段时钟从上一阶段真实归属起算；MS-03 已释放不可强制回滚，未释放到期可退；MS-04 任一争议暂停后续并只处理全部剩余款；MS-05 重复接受/争议协议不得二次分配；MS-06 全额合计与每阶段金额保持守恒。

## 12. M6：Rewards

交付名单验证、1–100地址上限的实际Gas评估、全额预存、固定地址领取、到期回收。

RW-01 名单地址唯一且金额正数；RW-02 链上总额等于实际入金；RW-03 不在名单或重复领取失败；RW-04 开始/截止边界唯一；RW-05 已claim成credit但未withdraw的款不得被回收；RW-06 生效后无法改名单/提前撤回；RW-07 最长列表创建与领取预算通过，否则在发布前降低并版本化上限。

## 13. M7：发布与参赛准备

回归全部资金正常/失败/重复/超时路径；外部钱包兼容、手机截图、可访问性、性能预算；依赖与权限检查、独立安全审阅、隐私/条款和故障退出说明。主网前G-07必须全部满足，未通过可提供明确测试网演示。

材料：项目简介、目标用户与真实反馈、实际支持工具清单、架构图文字来源、演示录像、代码与版本基线、测试网/主网地址和交易、已知限制、ArcBox复用说明、赞助集成证据。未完成工具不录成假功能。登录后的赛事提交条件和截止时区需G-08确认；没有证据不宣称已提交或满足所有奖项条件。

## 14. 每阶段报告模板

- 范围：本阶段实现/未实现。
- Git：dev提交、PR、main是否变化。
- 测试：实际命令、退出码、网络/环境、证据位置；未执行项与原因。
- 部署：开发/正式分别列出，实际URL和构建ID，不用预计地址。
- 风险：阻塞门禁、资金/权限变化、已知问题。
- 下一步：仅下一阶段名称与用户所需动作；报告后停止。
