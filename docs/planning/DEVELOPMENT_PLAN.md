## 1. 最终目标与完成标准

交付可在 Monad 测试网完整演示的六工具支付站：Group、Split、Deliver、Attend、Milestones、Rewards，共用账号、工作台、规则预览、操作历史和资金退出入口。

每个工具都要能完成“创建 → 发布 → 执行 → 正常结算或异常退出 → 查询与恢复”，具备中英文、移动端和明确的钱包签名提示。资金以合约为准，网站和数据库不能授予提款权。不扩展到兑换、跨链、发币、借贷、法币通道或平台裁决争议。

完成分两层，不能混记：

1. **工程完成**：六工具代码、合约、页面、API、权限、恢复、必要测试与文档齐全；本地及 CI 验证通过，提交 main 并核验 Production 网站版本。
2. **发布验收完成**：实际资源隔离、测试网合约登记、真实钱包/设备、外部试用、安全复核和演示证据齐全。主网另经 G-07 授权，不属于默认工程完成。

## 3. 连续执行方式

普通单批请求只完成该批。用户明确授权“全阶段完成”后，按 **M1-C → M2-A → M2-B 工程项 → M3 → M4 → M5 → M6 → M7 工程项** 连续推进；M1-D、真实试用等外部验收可穿插补齐，不阻塞独立工程任务。

每阶段按相同顺序执行：

1. 读取本表、最新文件和远端 main，确认当前任务及影响范围。
2. 按规格先补状态机/合约与必要数据，再接 API、页面、恢复；同阶段形成可演示的完整流程。
3. 运行与改动相关的验证；阶段交付运行完整 CI，修复失败后再推进依赖该阶段的功能。
4. 更新本表、当前操作说明和实际验收记录，提交 main，核验 Production 自动构建与线上版本。
5. 在全阶段授权内继续下一阶段，不反复等待阶段确认。最终汇总交付、测试和剩余外部验收。

只有新增且未授权的资源/账户操作、真实签名、主网放行、破坏性数据变更或实质资金规则改变需要用户决定。缺少外部配合时写明依赖和待验证项，继续可独立完成的任务；不能用模拟结果代替真实验收。

效率约定：复用已安装依赖和固定版本工具；每次只读相关规格；日常变更做针对性验证，阶段交付跑全套；不为相同状态重复写报告，不建立未经需要的新目录、框架或通用抽象。
