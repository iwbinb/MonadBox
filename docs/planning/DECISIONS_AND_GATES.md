# 决策记录与放行条件

M0-B更新 · 2026-09-27。ADR-13按用户最新决定替代ADR-03；当前一个Worker+dev Preview，远端数据/后台功能关闭。

## 1. 用户明确的约束

U-01 仓库为 `iwbinb/MonadBox`；U-02 六工具集合站，先Group再Split组合；U-03 长期dev开发，PR合并main后Cloudflare自动发布；U-04 用户决定合并；U-05 M0-A已合并，本次仅M0-B工程基础，远端部署和链上验证另行验收。

技术与业务默认值是规格基线，不冒充用户逐项批准。不可逆资金规则变更必须修订规格并经阶段PR审阅，不能静默更改已发布订单。

## 4. 资金规则取舍保持不变

Group成功只代表达到成团条件；需要现实验收保护应使用Deliver/Milestones，不临时增加后台裁决权。Deliver/Milestones与Attend用明确期限和默认退出，不永久冻结，也不让管理员自由裁决；偏向及被滥用的风险需双方接受和真实验证。

仍有退款义务的钱继续留在原托管规则中，不能为了演示先分账又保证同一份本金可全退。M0-B不修改这些规则，也不实现资金逻辑。

## 5. ADR-13执行细则

main正式部署、dev Worker Previews，两个构建命令由单仓库脚本校验。用户在Cloudflare控制台连接GitHub，不给开发者管理token。首次工程部署不需要远端D1/R2/Queues，相关能力关闭，缺配置不能伪装正常。

后续资源通过单独PR绑定不同D1和私有R2，并实际测试。Preview消费者/Cron缺口必须先确定隔离方案，不能为了通过检查直接接生产队列。Foundry编译器与钱包SDK等未使用依赖延后到M0-C核验，不冒充本阶段已通过。

## 6. 变更模板

变更ID/日期、原规则、新规则、受影响角色/状态/旧订单/测试、权限或资金风险、用户批准、迁移/旧版退出办法、代码/部署版本。未合并决定不得覆盖既有Box条款。
